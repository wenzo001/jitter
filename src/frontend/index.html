执行方式

每天在窗口内随机挑一个时刻执行一次；结束早于开始视为跨午夜窗口（例如 23:50–00:10），按开始日计一次。

循环执行：每隔 N 秒 / 分钟 / 小时 / 天执行一次。第一次执行时间留空 = 从现在开始算；填了就从那个时刻起对齐（例如「从 09:00 开始，每 2 小时」→ 11:00、13:00…）。抖动会给每次再加 0–N 秒随机偏移。

接下来 7 次执行

当前未设置请求超时（requestTimeoutMs = 0）：如果目标地址一直不返回，这次执行会一直占着该任务。可以在 jitter.config.json 里设置 requestTimeoutMs（毫秒，建议 30000）。

成功条件（决定是否「命中」，不发通知也会记录）

三项都不填时，任意 2xx 视为命中；填写后需全部满足才算命中。条件表达式从 JSON 响应体按路径安全取值，例如 data.result.remindtype=0、data.error.code!=null、ok=true && $status=200；支持 =/==/!=/>/<、&&/||/!、三元与 $status。"0" 与 0 用 = 比较时相等；路径取不到则条件不成立，不会报错。只填表达式时不隐含 2xx 限制，需要限制状态码请写进表达式，如 $status>=200 && $status<300 && ...。响应体按最多 100 KiB 比较；超过上限会追加 [truncated]，此时条件表达式视为不匹配。

只有命中上面的成功条件才会发送；通知失败只写它自己的记录，不影响任务。

允许执行的星期（不选 = 每天）

到达执行时间后先判断：星期与时段不满足就直接跳过（不发任何请求）；配了前置 curl 时再发请求，按状态码/表达式判定。全部满足才发主请求，否则本次跳过并在记录里写明原因。本地条件与前置 curl 至少配一项；时段结束早于开始视为跨午夜。
